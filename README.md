> **【1.0.5 更新公告 · 2026-11-24】**

梦幻西游多开与窗口管理小工具（C# / WPF，单文件绿色版，免安装）。

只做**桌面层面**的批量启动、排列与多开辅助（窗口标题序号、按进程静音、掉线补开），不涉及任何游戏内操作、内存修改或外挂功能。

## 功能

| 模块 | 功能 |
|---|---|

| 窗口布局 | 自动适配（按比例与数量反算不重叠的尺寸）/ 自定义宽高 / 使用预设 / 不改变窗口大小；窗口间距可调；5 个窗口五点布局（左上 / 上中 / 右上 / 左下 / 右下），其他数量自动排布；按客户区对齐并补偿标题栏边框 |

| 运行日志 | 界面内查看，支持清空与导出为 txt |
| 托盘 | 关闭时可选最小化到托盘，托盘菜单可呼出主界面或退出 |

## 新版（C#）与老版（AHK）对比

老版本是用 AutoHotkey v2 写的脚本（仓库内存档的 `梦幻时空助手.ahk`），新版本是用 C# / WPF 重写的 `Nightforge`。两者功能范围一致（都只做窗口层面的事），差别主要在**易用性、稳定性和后续维护**上。

| 对比项 | 老版本（AutoHotkey） | 新版本（C# / WPF） |
|---|---|---|
| 安装与运行 | 脚本需要 AutoHotkey 运行环境，打包的 exe 依赖 AHK 运行时，部分安全软件可能拦截或误报 | 单文件 exe（约 67 MB），双击即用，免安装、无需另装运行时，被拦截误报的情况明显减少 |
| 界面 | AHK 自带 GUI，控件和样式比较简陋，高分屏下容易发虚 | WPF 界面，支持高 DPI 缩放，布局随窗口自适应，观感与操作都更接近正常软件 |
| 热键录制 | 录制能力较弱，遇到系统已占用的组合键容易录完不生效 | 窗口级按键捕获，冲突时给出提示并可改绑，录制完立即生效 |
| 窗口布局 | 排列方式固定、可调参数少 | 自动适配按比例反算尺寸，可调宽高与间距；5 个窗口五点布局，其他数量自动排布；按客户区对齐 |
| 配置 | `config.ini` | 沿用 `config.ini`，老版配置放到新程序旁边即可直接迁移 |
| 更新 | 需要自己留意更新并手动下载覆盖 | 启动后静默检查新版本，1.0.2 起支持后台自动下载并下次启动自动替换，不必再手动下载 |
| 日志 | 文本日志，需要自己去翻文件 | 界面内直接查看，支持清空、导出为 txt |
| 托盘 | 基础托盘菜单 | 关闭窗口可选最小化到托盘，托盘菜单可呼出主界面或退出 |
| 稳定性 | 解释型脚本，长时间运行偶发异常，出错时提示信息有限 | 编译型程序，模块化结构，异常统一记录到日志，长时间挂机更省心 |
| 可维护性 | 单文件脚本，改动全靠手写，容易改出新问题 | 源码按功能拆分为 Models / Services 等模块，类型安全，便于持续修 bug 和加功能 |

**一句话总结**：老版本胜在体积小、源码轻；新版本胜在开箱即用、界面清晰、热键与更新更省心，后续维护和加功能也更容易。功能上两者完全一致，建议直接用新版本。

## 下载与运行

1. 到本仓库 **Releases** 页面下载最新版 `Nightforge.exe`（单文件，约 67 MB，Windows x64）。
2. 双击运行即可，无需安装、无需 .NET 运行时。
3. 配置保存在程序同目录的 `config.ini`，从旧版 AutoHotkey 版本迁移时，把旧的 `config.ini` 放到程序旁边即可直接复用。

## 更新方式

1.0.2 起支持自动更新，流程如下：

- 程序启动 3 秒后**静默联网检查**新版本，之后每 6 小时检查一次；
- 发现新版本后，若「设置 → 自动下载更新」为开（默认开），程序会在后台自动下载新版整包（约 67 MB），下载完成后自动校验文件大小与 SHA-256，校验不通过直接丢弃，旧版本不受影响；
- 1.0.4 起下载走**多线路**：清单里给的镜像地址依次尝试，全部失败才用官方直链；单条线路失败会先原地重试一次，仍失败才切换。断点续传让中途断网可以从上次位置继续，不必重下整包；
- 下载完成后会提示可选择「立即重启更新」马上生效，或「下次启动更新」不打断当前使用；选择后者时，下次打开软件会自动替换为新版；
- 若关闭了「自动下载更新」，仍然只提示版本信息，由你自行到 Releases 下载；
- 程序放在只读目录或没有写入权限时，会自动退回「跳转网页手动下载」，不会卡住。

提示：1.0.2 是第一个支持自动更新的版本，当时仍需手动下载一次；**从 1.0.2 起的新版本都会自动更新**。若 1.0.2 / 1.0.3 卡在下载不动（旧版只会连官方直链，而该域名在部分网络下不可用），手动下载一次 1.0.4 即可，之后都会自动更新。

更新排查：程序目录下的 `update.log` 记录了每次检查与下载的完整过程（发现哪个版本、走了哪条线路、失败原因、校验结果）。反馈问题时把这个文件一起发来即可。

版本号来源：仓库根目录的 `version.json`（主通道，改一行就能推送更新通知）；若读取失败会退回 GitHub Releases 接口作为备用通道。清单里可同时给出 `exeUrl`（单地址，兼容老客户端）与 `exeUrls`（多地址列表，含镜像）。镜像只是同一条文件的另一条路，下载后仍按 SHA-256 校验，被改动过的文件会被丢弃。

## 画面比例说明

游戏把画面比例存在自己的设置文件 `LocalData\UserDefault.xml` 的 `DeviceScreenResolution` 一项里，可选值只有五个：`Ratio16to9`、`Ratio4to3`、`RatioPortrait`、`Ratio16to9_4K`、`Ratio4to3_4K`。本程序读写的就是这一项，等同于在启动器里切换，所以有几点要注意：

- 改完**只对之后启动的窗口生效**，已经在跑的窗口不会变，需要关掉重开；
- 修改时**游戏必须全部关闭**（`MyGame_x64r` 等进程不在运行）——游戏退出时会用内存里的值回写这个文件，运行中改了会被覆盖回去；
- 首次修改前会把原文件备份到程序目录的 `UserDefault.xml.bak`，出问题直接覆盖回去即可；
- 排列用的窗口尺寸由「数量 + 比例 + 屏幕工作区」反算，客户区正好等于所选比例，不会出现黑边。
